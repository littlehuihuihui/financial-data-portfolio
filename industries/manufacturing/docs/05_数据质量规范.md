# 制造业 · 数据质量规范 v3.1

> 生产、设备、质量、供应链全链路数据质量保障，支撑智能制造决策

## 一、数据质量6维度体系

### 1.1 完整性（Completeness）

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 | 处理方式 |
|---------|---------|---------|---------|---------|
| 设备实时数据 | 设备心跳数据上报频率，丢包率监控 | 丢包率 < 1% | P1 高 | 排查网络、传感器、网关 |
| 生产报工数据 | 工单报工条数与MES对比 | 差异率 = 0% | P1 高 | 补数，确保生产数据完整 |
| 质检数据 | 检验批次完整性，必检工序是否都有检验记录 | 完整率 > 99.5% | P1 高 | 补录检验记录，追溯漏检 |
| 物料出入库 | 出入库单据与WMS对比 | 差异率 = 0% | P1 高 | 逐单核对，补全数据 |
| 维度主数据 | 产线、产品、设备、人员维度完整性 | 缺失数 = 0 | P2 中 | 补全主数据，关联默认值 |

### 1.2 准确性（Accuracy）

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 | 处理方式 |
|---------|---------|---------|---------|---------|
| 传感器数据 | 传感器数值在合理范围内，无异常跳变 | 异常值 < 0.5% | P2 中 | 异常值过滤，插值补全 |
| 产量数据 | 报工产量与实际计数设备对比 | 差异率 < 0.5% | P1 高 | 校准设备，修正数据 |
| 工时数据 | 报工工时合理性，不超过班次时长 | 异常率 < 1% | P2 中 | 人工审核，异常修正 |
| 质量数据 | 不良代码标准化，在不良代码字典内 | 匹配率 = 100% | P1 高 | 统一编码，映射转换 |
| 库存数据 | 账实一致，盘点差异率 | 差异率 < 0.3% | P1 高 | 盘点调整，查明原因 |

### 1.3 一致性（Consistency）

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 | 处理方式 |
|---------|---------|---------|---------|---------|
| 工单状态流转 | 工单状态按流程正常流转，无跳变 | 异常率 = 0% | P1 高 | 修正状态，追溯异常原因 |
| 跨系统一致性 | ERP工单与MES工单数量、状态一致 | 差异率 = 0% | P1 高 | 双向对账，同步修正 |
| 指标口径一致性 | OEE/FPY等核心指标在不同看板一致 | 差异 = 0 | P1 高 | 统一口径，修正计算逻辑 |
| 维度一致性 | 产线、产品编码跨系统统一 | 匹配率 = 100% | P2 中 | 主数据统一管理 |
| 时间一致性 | 各系统时间同步，偏差不超过1分钟 | 偏差 < 60秒 | P2 中 | NTP时间同步 |

### 1.4 及时性（Timeliness）

| 数据类型 | 延迟要求 | 告警阈值 | 业务影响 |
|---------|---------|---------|---------|
| SCADA设备数据 | 秒级（< 5秒） | 延迟 > 30秒告警 | 实时监控失效，异常发现不及时 |
| MES生产数据 | 准实时（< 5分钟） | 延迟 > 15分钟告警 | 生产看板不准，调度滞后 |
| 质量检验数据 | 准实时（< 10分钟） | 延迟 > 30分钟告警 | 质量问题发现慢，不良扩大 |
| 离线ODS层 | T+1 凌晨6:00前 | 延迟 > 30分钟告警 | 影响日报、月结 |
| 日汇总看板 | 每日上午8:00前可用 | 延迟 > 1小时告警 | 早会生产日报延迟 |

### 1.5 有效性（Validity）

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 |
|---------|---------|---------|---------|
| 设备状态 | 状态值在枚举范围内（运行/停机/待机/故障） | 异常率 = 0% | P2 中 |
| 工单状态 | 状态值在枚举范围内（创建/开工/完工/取消） | 异常率 = 0% | P1 高 |
| 时间格式 | 时间戳格式合法，在合理范围 | 异常率 < 0.1% | P2 中 |
| 数值范围 | 温度、压力、转速等工艺参数在规格内 | 超限告警 | P1 高 |
| 编码规范 | 工单号、物料号、设备号符合编码规则 | 异常率 = 0% | P2 中 |

### 1.6 唯一性（Uniqueness）

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 |
|---------|---------|---------|---------|
| 工单号 | 同一工单号唯一 | 重复率 = 0% | P0 紧急 |
| 设备日志 | 同一设备同一时间戳唯一 | 重复率 < 0.1% | P2 中 |
| 检验单号 | 同一检验单号唯一 | 重复率 = 0% | P1 高 |

## 二、设备实时数据专项质量规范

### 2.1 SCADA数据采集质量保障

| 环节 | 质量风险 | 监控指标 | 保障措施 |
|------|---------|---------|---------|
| **传感器层** | 传感器故障、漂移、接触不良 | 数值跳变率、零值率、超量程率 | 定期校准、异常值检测、冗余传感器 |
| **网关层** | 网络波动、网关宕机、丢包 | 心跳丢失率、数据丢包率 | 断点续传、本地缓存、双网关冗余 |
| **传输层** | 网络延迟、丢包、乱序 | 延迟、乱序率 | MQTT QoS=1、消息队列缓冲 |
| **计算层** | Flink计算错误、状态丢失 | 实时离线一致性、数据量对比 | 幂等计算、Checkpoint、离线校准 |
| **存储层** | 时序库写入失败、数据丢失 | 写入成功率、查询完整性 | 副本机制、定期备份、离线备份 |

### 2.2 设备数据清洗规则

```sql
-- DWD层设备数据标准清洗逻辑
INSERT OVERWRITE TABLE dwd.dwd_device_fact PARTITION(dt='${dt}')
SELECT
    device_id,
    ts AS event_time,
    device_status,
    -- 1. 异常值过滤：传感器数值在合理范围内
    CASE WHEN temperature BETWEEN 0 AND 200 THEN temperature ELSE NULL END AS temperature,
    CASE WHEN speed BETWEEN 0 AND 3000 THEN speed ELSE NULL END AS speed,
    CASE WHEN current BETWEEN 0 AND 100 THEN current ELSE NULL END AS current,
    -- 2. 跳变检测：与前后值差异超过阈值标记为异常
    CASE WHEN ABS(temperature - LAG(temperature) OVER(PARTITION BY device_id ORDER BY ts)) > 50
         THEN '异常跳变' ELSE '正常' END AS data_quality_flag,
    -- 3. 状态合法性校验
    CASE WHEN device_status IN ('运行','待机','停机','故障') THEN device_status ELSE '未知' END AS status_clean,
    etl_time
FROM ods.ods_device_log
WHERE dt = '${dt}'
  -- 4. 时间合理性过滤
  AND ts BETWEEN '${dt} 00:00:00' AND '${dt} 23:59:59'
  -- 5. 去重：同一设备同一毫秒只保留一条
  QUALIFY ROW_NUMBER() OVER(PARTITION BY device_id, ts ORDER BY etl_time DESC) = 1;
```

### 2.3 OEE计算质量保证
1. **时间基准统一**：所有设备使用统一的班次时间，避免时区、时钟偏差
2. **停机原因分类准确**：停机原因标准化，自动分类+人工校验结合
3. **标准节拍准确**：标准节拍由工艺部门确认，定期更新，不同产品分开计算
4. **质量数据联动**：OEE质量率与质检系统数据联动，不单独统计
5. **人工校准机制**：每班结束后班组长可确认修正OEE数据，有修改留痕

## 三、质量检验数据专项规范

### 3.1 质量数据质量要求
1. **检验完整性**：每道必检工序必须有检验记录，不漏检
2. **不良编码统一**：所有不良代码标准化，同一不良只有一个编码
3. **检验数量准确**：检验数、合格数、不良数逻辑一致（检验=合格+不良）
4. **责任判定清晰**：不良责任部门、原因分类明确，便于后续分析
5. **SPC数据连续**：计量型数据连续采集，样本量足够，间隔均匀

### 3.2 质量数据校验规则
```sql
-- 质量数据校验SQL示例
SELECT 
    '检验数量逻辑错误' AS check_type,
    COUNT(*) AS error_count
FROM ods.ods_quality_inspection
WHERE dt = '${dt}'
  AND inspect_qty != qualified_qty + defect_qty + rework_qty;

-- 不良代码合法性校验
SELECT 
    '不良代码不存在' AS check_type,
    COUNT(DISTINCT defect_code) AS error_count
FROM ods.ods_quality_inspection
WHERE dt = '${dt}'
  AND defect_code NOT IN (SELECT defect_code FROM dim_defect_code);
```

## 四、质量问题处理与SLA

### 4.1 告警分级响应
- **P0 紧急**：核心系统中断、生产数据大面积丢失、设备监控失效 → 30分钟响应，立即处理
- **P1 高**：OEE/FPY等核心指标异常、生产数据不一致、质量数据漏检 → 2小时响应
- **P2 中**：少量设备数据异常、非核心指标偏差、主数据缺失 → 当日响应
- **P3 低**：格式优化、边缘场景、建议类 → 排期处理

### 4.2 数据修复原则
1. **原始数据不修改**：源系统数据不直接修改，问题数据标记，修正逻辑在数仓层处理
2. **修改留痕**：所有数据修正必须有记录，谁改的、为什么改、改了什么
3. **追溯可审计**：生产质量数据属于重要数据，所有变更支持审计追溯
4. **离线校准**：实时数据每日用离线数据校准一次，保证最终一致性
