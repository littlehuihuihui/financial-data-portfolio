# 互联网行业 · 数据分析方法论（完整版 v3.0）

与零售财务、制造业框架统一，面向互联网**用户增长 + 营销策略 + 商业变现 + 产品分析**四大领域全场景，严格遵循AARRR海盗模型与增长黑客方法论。

**业务主线：** 获客 → 激活 → 留存 → 变现 → 推荐  
**四大分析领域：** 用户增长分析、营销策略分析、商业变现分析、产品迭代分析  
**核心目标：** 拉新、促活、留存、付费、传播、盈利  
**北极星指标：** 因产品而异：内容产品=DAU/使用时长，电商=GMV，SaaS=MRR/付费率，工具=核心功能使用率

---

## 一、四大分析领域全景

### 1.1 用户增长分析（User Growth）
> 核心回答：用户从哪来？为什么留不住？怎么提升活跃？
- 用户规模与结构（DAU/MAU、新老用户、分层）
- 用户留存与流失（同期群、留存曲线、流失预警）
- 用户生命周期（引入期/成长期/成熟期/衰退期/流失期）
- 用户画像与分群（属性/行为/偏好/价值标签）

### 1.2 营销策略分析（Marketing Analytics）
> 核心回答：钱花在哪了？效果怎么样？怎么提升ROI？
- 渠道投放分析（获客成本、渠道质量、ROI对比）
- 营销活动分析（活动效果、参与转化、投入产出）
- A/B测试体系（实验设计、显著性检验、效果评估）
- 归因分析（多触点归因、渠道功劳分配、投放优化）
- 用户触达（Push/短信/站内信、触达效果、召回策略）

### 1.3 商业变现分析（Business Analytics）
> 核心回答：怎么赚钱？赚多少？能不能持续盈利？
- 营收分析（收入结构、ARPU/ARPPU、付费率、复购）
- LTV/CAC模型（用户生命周期价值、获客成本、单位经济）
- 商业化变现（广告/会员/电商/增值服务、各变现方式占比）
- 成本分析（获客成本、运营成本、服务器成本、毛利）
- 单位经济模型（单用户/单客户全生命周期盈亏平衡）

### 1.4 产品迭代分析（Product Analytics）
> 核心回答：产品好不好用？用户爱不爱用？怎么优化？
- 功能分析（功能渗透率、使用频次、使用时长）
- 漏斗转化（注册漏斗、付费漏斗、核心流程转化率）
- 用户路径分析（行为流、桑基图、流失点定位）
- 版本迭代分析（版本对比、新功能效果、bug影响）
- 产品健康度（崩溃率、启动时长、错误率、NPS）

## 二、六层分析框架（通用所有领域）

### 第一层 · 描述性分析（What happened? 发生了什么）

> 回答：现在是什么状态？核心指标是多少？和目标/同期比怎么样？

| 分析领域 | 核心场景 | 核心指标 |
|---------|---------|---------|
| **用户增长** | 用户规模、活跃结构、留存水平、流失情况 | DAU/MAU、新增、留存率、流失率 |
| **营销策略** | 渠道投放、活动效果、触达情况 | 渠道新增、CAC、ROI、活动参与率 |
| **商业变现** | 营收规模、付费情况、成本结构 | 营收、ARPU、付费率、毛利率 |
| **产品分析** | 功能使用、转化情况、产品健康 | 功能渗透率、漏斗转化率、崩溃率 |

---

### 第二层 · 诊断性分析（Why it happened? 为什么发生）

> 回答：指标异常的原因是什么？哪个环节/渠道/版本出了问题？

| 分析领域 | 异常场景 | 下钻维度 | 诊断方法 |
|---------|---------|---------|---------|
| **用户增长** | DAU下滑、留存下降、流失升高 | 渠道→版本→用户分层→地域→功能 | 同期群对比、维度拆解、路径分析 |
| **营销策略** | CAC上升、ROI下降、活动效果差 | 渠道→素材→定向→人群→时间 | 归因分析、渠道分层、A/B对比 |
| **商业变现** | 营收下降、付费率低、LTV低 | 付费点→价格→用户分层→渠道→产品 | 漏斗分析、RFM分层、付费路径分析 |
| **产品分析** | 功能使用率低、转化漏斗流失高 | 入口→版本→用户分层→机型 | 热力图、用户路径、可用性分析 |

---

### 第三层 · 预测性分析（What will happen? 会发生什么）

> 回答：未来会怎么样？有没有风险？机会在哪里？

| 分析领域 | 预测场景 | 预测方法 | 业务价值 |
|---------|---------|---------|---------|
| **用户增长** | DAU预测、流失预测、用户规模 | 时间序列、留存系数、机器学习 | 资源规划、目标制定、提前挽留 |
| **营销策略** | 活动效果预测、渠道ROI预测 | 历史回归、人群相似性模型 | 预算分配、投放优化、效果预估 |
| **商业变现** | LTV预测、营收预测、付费转化预测 | Cohort生存分析、回归模型 | 定价策略、商业规划、利润预测 |
| **产品分析** | 功能渗透预测、用户行为预测 | 用户行为序列模型 | 产品规划、优先级排序 |

---

### 第四层 · 处方性分析（What should we do? 应该怎么做）

> 回答：针对问题应该采取什么措施？不同方案的预期效果是什么？

| 分析领域 | 问题场景 | 优化方案 | 预期效果 |
|---------|---------|---------|---------|
| **用户增长** | 留存低、流失高、活跃差 | 新手引导优化、核心行为前置、分层运营 | D1留存提升5-15%，流失降3-8% |
| **营销策略** | ROI低、获客贵、转化差 | 关停低质渠道、素材优化、精准定向、A/B测试 | CAC降20-40%，ROI提升30%+ |
| **商业变现** | 付费率低、ARPU低、盈利差 | 付费点优化、价格测试、会员体系、增值服务 | 付费率提升2-10%，ARPU提升15%+ |
| **产品分析** | 转化低、功能没人用、体验差 | 路径优化、入口调整、引导加强、体验打磨 | 核心转化提升10-30%，功能渗透提升20%+ |

---

### 第五层 · 根因分析（Root Cause 根本原因是什么）

> 回答：问题的根本原因是什么？区分相关性和因果性。

| 根因方法 | 适用场景 | 互联网应用示例 |
|---------|---------|--------------|
| **A/B测试** | 产品改动、运营策略、UI变化、定价 | 新注册流程上线，A组老流程B组新流程，B组留存高10%→确定因果关系 |
| **维度拆解法** | 指标异常定位 | DAU降10%→拆渠道发现某渠道掉50%→拆素材发现素材违规被限流→根因：素材违规 |
| **用户路径分析** | 转化流失、行为异常 | 支付页流失高→看路径发现很多用户去了优惠券页没回来→根因：返回路径设计问题 |
| **同期群Cohort** | 留存变化、版本影响 | 留存从35%降到25%→分注册周发现v2.5版本后注册的用户留存都低→根因：v2.5核心功能bug |
| **相关性vs因果性** | 避免错误归因 | 用了A功能的用户留存高≠A功能提升留存，可能是高留存用户本来就爱用A→A/B测试验证 |
| **5Why分析法** | 单一明确问题 | 流失率高→用户不回来→没价值→找不到内容→推荐不准→冷启动标签少→根因：新用户冷启动策略 |
| **用户访谈/可用性测试** | 定性根因 | 数据发现某页面流失高，但不知道为什么→找5-10个用户测试，发现按钮文案看不懂 |

---

### 第六层 · 闭环优化（How to improve continuously? 如何持续增长）

> 回答：如何形成闭环，数据驱动迭代，持续优化。

| 闭环环节 | 互联网落地方法 |
|---------|--------------|
| **Plan 假设** | 基于数据发现问题，提出增长假设，设计实验方案，确定指标和样本量 |
| **Do 实验** | 开发上线A/B测试，分流用户，收集数据，保证实验科学性（统计显著性） |
| **Check 验证** | 分析实验结果，看核心指标是否提升，有没有负向影响，统计是否显著 |
| **Act 推广** | 实验有效→全量上线，标准化，复制到其他场景；实验无效→复盘原因，提出新假设 |
| **增长闭环** | 北极星指标拆解→找机会点→做实验→看结果→全量/迭代→下一个循环，每周增长例会 |
| **数据产品化** | 核心指标看板自动监控、异常自动告警、分析结论自动推送、用户分群自动触达 |
| **指标体系迭代** | 随着产品发展更新北极星指标、完善指标字典、数据质量监控 |

## 🚀 互联网专属分析工具箱

| 分析方法 | 核心思想 | 应用场景 | 所属领域 |
|---------|---------|---------|---------|
| **AARRR海盗模型** | 获客→激活→留存→变现→推荐，全用户生命周期 | 增长框架、产品全链路分析 | 用户增长 |
| **RARRA留存优先模型** | 留存→激活→推荐→变现→获客，以留存为核心 | 产品进入成长期后，从拉新转向留存 | 用户增长 |
| **同期群Cohort分析** | 按相同特征分组，跟踪后续行为 | 留存分析、版本效果、用户生命周期 | 用户增长 |
| **RFM用户分层** | 最近消费/消费频率/消费金额 | 用户价值分层、精准营销、流失预警 | 用户增长/营销 |
| **用户画像标签体系** | 基础属性/行为/偏好/价值多维标签 | 个性化推荐、精准营销、用户分群 | 用户增长 |
| **漏斗分析** | 每一步转化率，找流失点 | 注册转化、付费转化、核心流程 | 产品/营销 |
| **用户路径分析** | 行为流向桑基图，找最优路径/流失点 | 产品体验优化、导航设计、流失定位 | 产品分析 |
| **热力图分析** | 点击/浏览/注意力分布 | UI优化、页面布局、广告位效果 | 产品分析 |
| **事件分析** | 行为事件多维下钻、趋势对比 | 功能使用、行为统计、自定义指标 | 产品分析 |
| **A/B测试** | 随机对照实验，确定因果关系 | 产品迭代、运营策略、UI、定价 | 全领域通用 |
| **归因分析** | 多触点功劳分配（首次/末次/线性/时间衰减） | 渠道效果评估、投放预算分配 | 营销策略 |
| **LTV/CAC模型** | 生命周期价值/获客成本，判断商业健康度 | 渠道评估、商业模式验证、单位经济 | 商业分析 |
| **魔法数字** | 和留存高度相关的关键行为次数 | 新用户激活、Aha时刻发现 | 用户增长/产品 |
| **单位经济模型** | 单用户全生命周期收入-成本，算盈亏平衡点 | 商业模式验证、规模化可行性判断 | 商业分析 |
| **同期群LTV** | 按注册群跟踪生命周期价值曲线 | 用户价值预测、渠道质量评估 | 商业分析 |

## 🏗️ 数仓模型设计

### 数仓分层架构
```
ADS 应用层 → 5+主题看板视图（用户/营销/商业/产品）
 ↑
DWS 汇总层 → 日/周/月汇总表（用户日汇总、渠道日汇总、营收日汇总）
 ↑
DWD 明细层 → 事实表（用户行为事实、订单事实、曝光事实、点击事实）
 ↑
DIM 维度层 → 维度表（用户、日期、渠道、产品、版本、设备）
 ↑
ODS 贴源层 → 原始数据（业务库同步、埋点日志、第三方API）
```

### 核心事实表
1. **dwd_user_event_fact**：用户行为事件事实表（事件粒度）
2. **dwd_order_fact**：订单事实表（订单粒度）
3. **dwd_exposure_fact**：曝光事实表（广告/内容曝光粒度）
4. **dwd_click_fact**：点击事实表（点击粒度）
5. **dwd_session_fact**：会话事实表（会话粒度）

### 核心维度表
1. **dim_user**：用户维度（SCD2拉链表）
2. **dim_date**：日期维度
3. **dim_channel**：渠道维度
4. **dim_product**：产品/版本维度
5. **dim_device**：设备维度
6. **dim_event**：事件类型维度

### ER图关系（星型模型）
```
                    ┌─────────────┐
                    │  dim_date   │ 日期维度
                    └──────┬──────┘
                           │
┌──────────┐    ┌──────────┴──────────┐    ┌──────────────┐
│ dim_user │────│ dwd_user_event_fact │────│ dim_channel  │
└──────────┘    └──────────┬──────────┘    └──────────────┘
                           │
                    ┌──────┴──────┐
                    │ dim_device  │ 设备维度
                    └─────────────┘
                           │
                    ┌──────┴──────┐
                    │ dim_event   │ 事件维度
                    └─────────────┘
```

## 🔗 数据血缘关系

### 核心指标血缘（DAU指标为例）
```
业务源：用户登录日志 / 埋点SDK
    ↓
ODS层：ods_user_event（原始事件日志）
    ↓ 清洗、去重、脱敏
DWD层：dwd_user_event_fact（用户行为明细事实表）
    ↓ 按天+用户去重
DWS层：dws_user_daily（用户日汇总表，每日每个用户一行）
    ↓ 按日期统计去重用户数
ADS层：ads_dau_dashboard（DAU看板视图）
    ↓
看板：DAU总览看板
```

### 核心指标血缘（LTV指标为例）
```
业务源：订单表 + 用户表
    ↓
ODS层：ods_order_info / ods_user_info
    ↓ 清洗、关联
DWD层：dwd_order_fact（订单明细事实表）
    ↓ 按用户+日期汇总
DWS层：dws_user_payment_daily（用户日付费汇总）
    ↓ 按注册Cohort累计计算LTV
ADS层：ads_ltv_analysis（LTV分析视图）
    ↓
看板：商业分析 / LTV看板
```

### 数据血缘管理原则
1. **全链路追踪**：每个指标都能追溯到原始源表
2. **影响分析**：修改上游表时，能知道影响哪些下游指标
3. **口径一致性**：同一指标在不同看板来源必须一致
4. **元数据记录**：每张表、每个字段都有中文注释和业务含义
