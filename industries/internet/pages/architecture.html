ETL调度与数据血缘
数仓分层详解

ODS → DIM → DWD → DWS → ADS 五层架构，每一层有明确的定位和数据粒度。

分层定义与数据粒度

ODS · 操作数据层
颗粒度：原始日志/单据级（一行一次操作或一条主数据）。8 张表，核心是 ods_device_operation_log（一行 = 设备上一次操作：开机/点击/播放/支付），另含设备档案、用户档案、内容目录、渠道投放、订单、留存同期群、运营活动。
DIM · 维度层
颗粒度：主数据实体（一行一个设备/用户/产品线/渠道/操作类型/日期）。6 张表：dim_product_line 定义 launcher/vod/live/cashier 四产品线；dim_event_action 定义各产品线下的操作类型与漏斗映射。
DWD · 明细宽表层
颗粒度：清洗后的明细（一行一次操作或一行一用户/一会话）。3 张宽表：dwd_device_operation_wide（操作日志 + 冗余设备/用户/内容/渠道）、dwd_user_wide（用户行为与付费汇总）、dwd_session_wide（一行一会话）。
DWS · 汇总数据层
颗粒度：按日×主题预聚合。5 张表：用户日汇总（日×渠道）、产品线日汇总（日×launcher/vod/live/cashier）、留存日汇总、渠道日汇总、付费日汇总（日×渠道×产品线）。
ADS · 应用数据层
颗粒度：看板指标切片。8 个视图 + v_product_line_analysis 产品线分析，封装 DAU、留存、漏斗、LTV、RFM 等指标口径。

记忆口诀：ODS 存原始 → DIM 定口径 → DWD 宽表洗 → DWS 先算好 → ADS 给业务用。

宽表建模思路

internet_analytics 采用宽表优先：渠道名称、用户标签冗余进 dwd_user_wide / dwd_event_wide，看板查询无需 JOIN 多张维度表。

  • user_id → dim_user（画像 / 生命周期 / 付费标签）
  • channel_code → dim_channel（信息流 / 搜索 / 应用商店 等）
  • event_type → dim_event_type（浏览 / 注册 / 激活 / 付费）
  • event_date → dim_date（年 / 月 / 日下钻）
数据源与技术栈

业务数据来源

数仓底座为机顶盒/OTT 设备操作日志（开机 boot、点击 click、播放 play_start/play_end、频道进入 channel_enter、下单 order_submit、支付 pay_success），按产品线分流。样例灌入见 database/seed_internet_data.py。

产品线典型操作ODS 落表分析用途
launcher 桌面开机、首页点击、退出ods_device_operation_logDAU、开机率、桌面渗透
vod 点播选片、播放、暂停、完播ods_device_operation_log + ods_content_catalog播放时长、内容偏好、完播率
live 直播进入频道、观看直播ods_device_operation_log频道收视、直播时长
cashier 收银台提交订单、支付成功ods_subscription_order付费转化、ARPU、续费
  • 样例区间：2024-01 ~ 2026-07 · 约 6000 用户 / 6000 设备 · 5 渠道 · 百万级操作日志
  • ETL：操作日志 ODS → dwd_device_operation_wide → 用户/产品线/渠道 DWS → ADS 视图

数据库与计算引擎选型

互联网增长以海量埋点 + 准实时行为分析为主；本地作品集用 MySQL，生产典型组合为 Hive/MaxCompute（离线）+ ClickHouse（行为 OLAP）+ Kafka/Flink（实时）。规范见 docs/03_技术栈选型说明.md。
