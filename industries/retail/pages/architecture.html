血缘应用：问题溯源与变更影响

问题溯源（自下而上）：看板指标异常时，从 ADS 定位月份/维度 → 下钻 DWS → 回查 DWD 宽表 → 对比 ODS 原始单据，逐层锁定口径、清洗或源数据问题。

变更影响（自上而下）：改 ETL 或指标口径前查下游 ADS 与 13 主题看板；变更后重跑灌数并对账（差异≤2%），回归 API(:5000)。

数仓分层详解

ODS → DIM → DWD → DWS → ADS 五层架构（Kimball）；看板 SQL 只读 DWS/ADS。

分层定义与数据粒度

ODS · 操作数据层
颗粒度：原始单据级。8 张表：ods_orders / payment / purchase / inventory / expense / store_pnl / ad_cost / budget，贴源 ERP/CSV。
DIM · 维度层
颗粒度：主数据实体。5 张表：dim_brand / channel / category / store / date，统一编码映射。
DWD · 明细宽表层
颗粒度：清洗后明细。3 张宽表：dwd_sales_wide / expense_wide / inventory_wide（宽表优先，冗余维度名称）。
DWS · 汇总数据层
颗粒度：日/月预聚合。5 张表：dws_sales_daily/monthly · expense_monthly · inventory_daily · store_daily。
ADS · 应用数据层
颗粒度：看板指标切片。8+ 视图封装经营/品牌/渠道/杜邦/现金流/预算/库存等口径。

记忆口诀：ODS 存原始 → DIM 定口径 → DWD 宽表洗 → DWS 先算好 → ADS 给业务用。

宽表建模思路

retail_finance 采用宽表优先：品牌/渠道/品类/门店名称冗余进 DWD，看板查询少 JOIN。

  • brand_code → dim_brand
  • channel_code → dim_channel
  • category_code → dim_category
  • store_code → dim_store
  • order_date → dim_date
