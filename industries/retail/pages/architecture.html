⚙️ 数据仓库与管道架构

ODS → DIM → DWD → DWS → ADS 五层数仓（sql6_portfolio_model/）；含 ERP 数据源映射/对账、数据源与数据库选型，看板与对账 API 直接消费 DWS/ADS。作品集版 · 21 表 + 8 视图 = 29 对象

分层是什么？每一层存什么粒度的数据？

ODS · 操作数据层
颗粒度：原始单据级（一行一订单/一笔支付等）。Operational Data Store。贴近 ERP/CSV 的原始数据落地（8 张表：ods_orders、ods_payment 等），保留业务主键与审计字段，不做复杂加工。
DIM · 维度层
颗粒度：主数据实体（一行一品牌/渠道/品类/门店/日期）。五张维度表（dim_*），供 ODS→DWD ETL 做编码映射与名称冗余。
DWD · 明细宽表层
颗粒度：清洗后的明细宽表（一行一事实 + 冗余维度名）。dwd_sales_wide、dwd_expense_wide、dwd_inventory_wide，查询最多 1–2 张表。
DWS · 汇总数据层
颗粒度：按日/月 × 品牌 × 渠道 × 品类预聚合。dws_sales_daily 等 5 张表，看板查询更快。
ADS · 应用数据层
颗粒度：看板/API 指标切片。面向报表 / Tableau / Web API 的 8 个业务视图（v_overview、v_dupont 等），封装指标口径。

记忆口诀：ODS 存原始 → DIM 定口径 → DWD 宽表洗 → DWS 先算好 → ADS 给业务用。

宽表建模关系

sql6 采用宽表优先：维度名称冗余进 dwd_sales_wide，看板查询无需 JOIN 维度表。

  • brand_code → dim_brand（跃动Pro / Life / Go）
  • channel_code → dim_channel（抖音 / 天猫 / 京东 / 线下直营 等）
  • category_code → dim_category（鞋类 / 服装 / 配件）
  • order_date → dim_date（年 / 季 / 月 / 日下钻）

血缘应用：问题溯源与变更影响

问题溯源（自下而上）：看板异常时，从 ADS 定位 → DWS 下钻 → DWD 订单抽样 → ODS 对比源数据，逐层锁定根因。

变更影响（自上而下）：改 ETL 或口径前查下游依赖，评估需回归的 ADS 与 Tableau 工作表；变更后重跑 ETL 并对账。
