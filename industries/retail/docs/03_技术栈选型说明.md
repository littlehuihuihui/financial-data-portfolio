# 技术栈选型与数据源接入规范（零售财务行业）

## 一、技术栈选型说明

### 1.1 选型原则
- **财务准确性优先**：财务数据零差错，一致性、可追溯性是第一位
- **本地开发优先**：个人学习/作品集使用MySQL，轻量易部署，SQL标准兼容
- **生产环境分层**：根据企业规模选择不同技术栈，避免过度设计
- **合规审计要求**：财务数据必须可追溯、可审计、留痕完整
- **平滑迁移**：本地SQL 90%以上兼容生产环境Hive语法，迁移成本低

### 1.2 各环境技术栈对比

| 组件 | 本地开发环境 | 中小企业生产 | 中大型企业生产 | 集团级（阿里云） |
|------|-------------|-------------|---------------|----------------|
| **ERP/财务系统** | MySQL模拟 | 用友/金蝶ERP | SAP ECC/S4 HANA | SAP S/4 HANA Cloud |
| **关系型数据库** | MySQL 8.0 | MySQL 8.0 | Oracle/MySQL | PolarDB |
| **数仓存储（离线）** | MySQL 8.0 | MySQL 8.0 | Hive 3.x (HDFS) | MaxCompute(ODPS) |
| **OLAP查询引擎** | MySQL视图 | ClickHouse 23.x | Presto/Trino | Hologres |
| **实时计算** | - | -（财务T+1为主） | Flink 1.17（实时营收） | Realtime Compute |
| **数据集成** | 存储过程 | DataX + Kettle | DataX + SAP CDC | DataWorks数据集成 |
| **任务调度** | 手动/crontab | DolphinScheduler 3.x | Airflow/DolphinScheduler | DataWorks调度 |
| **财务报表** | Excel导出 | FineReport | 帆软/Tableau | Quick BI + 财务报表系统 |
| **预算管理** | Excel | 自定义系统 | BPC/海波龙 | 阿里云EAS |
| **数据质量** | - | 自定义SQL校验 | Apache Griffin + 财务对账 | DataWorks数据质量 |
| **元数据/血缘** | 文档 | Datahub | Datahub/Atlas | DataWorks数据地图 |
| **可视化** | ECharts HTML | FineBI/Metabase | Tableau/Power BI | Quick BI |

### 1.3 为什么财务行业以离线T+1为主？
1. **准确性要求高**：财务数据必须对账一致，日结后数据才准确，实时数据意义不大
2. **审计可追溯**：所有数据变更必须留痕，T+1批量处理更容易审计
3. **业务节奏匹配**：财务月结、季结、年结都是周期性批量处理
4. **数据量适中**：交易数据量比互联网埋点小很多，不需要实时流处理
5. **合规要求**：财务数据修改必须有审批，不允许实时随意变更

### 1.4 为什么本地用MySQL？
1. **轻量易部署**：一个Docker即可启动，不需要SAP/Hadoop集群
2. **SQL标准兼容**：DDL/DML语法和Hive/Oracle高度兼容
3. **学习成本低**：大多数财务分析师都熟悉MySQL语法
4. **性能足够**：千万级交易数据MySQL完全能支撑学习和演示
5. **作品集友好**：面试官不需要搭环境就能跑起来看效果

## 二、数据源接入规范

### 2.1 零售财务源系统清单

| **HR系统** | 人事薪酬 | MySQL | 人员、薪资、组织架构 | 手动/API | 每月月结 | 人事组 |

### 2.2 数据同步策略

#### 离线同步（T+1，财务主流程）
```
适用场景：90%以上财务数据，凭证、报表、库存、费用等
调度时间：每日凌晨1:00-6:00，必须等业务系统日结完成后开始
同步方式：DataX全量+增量结合
- 主数据（科目、供应商、客户）：每日全量覆盖
- 交易数据（凭证、订单、流水）：基于业务日期增量同步
- 财务对账：同步完成后必须和源系统对账，差异率=0才能进入下一步
```

#### 准实时同步（小时级，经营看板用）
```
适用场景：销售日报、库存看板等经营分析用，非严格财务口径
同步方式：Canal捕获binlog → Kafka → 小时级汇总
延迟要求：<1小时
注意：实时数据仅供经营参考，正式财务数据以T+1日结后为准
```

#### 月度批量同步（月结）
```
适用场景：成本核算、折旧计提、税金计算、月结年结
调度时间：每月1-5号，上月月结完成后
同步方式：全量同步上月数据，触发成本计算、报表生成
```

## 三、各层ETL处理规范

### 3.1 ODS层 ETL规范
```sql
-- ODS层标准处理模板（财务凭证）
INSERT OVERWRITE TABLE ods.ods_finance_voucher PARTITION(dt='${dt}')
SELECT
    CAST(voucher_id AS BIGINT) AS voucher_id,
    TRIM(voucher_no) AS voucher_no,
    voucher_date,
    company_code,
    CAST(account_code AS CHAR(20)) AS account_code,
    -- 借贷方向统一
    CASE WHEN UPPER(dc_flag) IN ('D', 'DEBIT', '借') THEN 'D'
         WHEN UPPER(dc_flag) IN ('C', 'CREDIT', '贷') THEN 'C'
         ELSE NULL END AS dc_flag,
    CAST(amount AS DECIMAL(18,2)) AS amount,
    TRIM(summary) AS summary,
    supplier_id,
    customer_id,
    -- 审计字段
    CURRENT_TIMESTAMP() AS etl_time,
    '${dt}' AS dt
FROM source.fi_voucher
WHERE voucher_date = '${dt}'
  AND voucher_status = '已过账' -- 只取已过账凭证
  -- 借贷平衡校验（必须相等，否则报错）
  AND (SELECT SUM(CASE WHEN dc_flag='D' THEN amount ELSE -amount END)
       FROM source.fi_voucher WHERE voucher_date = '${dt}') = 0
-- 去重：同一凭证号同一行只保留一条
QUALIFY ROW_NUMBER() OVER(PARTITION BY voucher_no, line_no ORDER BY updated_at DESC) = 1;
```

**ODS层必须做的清洗：**
1. 字段类型统一（金额统一DECIMAL(18,2)，编码统一字符串）
2. 空值处理（NULL替换为默认值）
3. 编码统一（科目、部门、物料编码全公司统一）
4. **财务校验**：借贷平衡、金额非负、凭证状态、日期合法性
5. 敏感数据脱敏（银行账号、客户信息）
6. 增加dt分区字段和etl_time时间戳

### 3.2 DIM层 ETL规范
```sql
-- 维度表处理模板（会计科目维度）
INSERT INTO dim.dim_account
SELECT
    account_id,
    account_code,
    account_name,
    account_level,
    parent_account_code,
    account_type, -- 资产/负债/权益/收入/成本/费用
    start_date,
    CASE WHEN end_date = '9999-12-31' AND old.account_id IS NOT NULL THEN DATE_SUB('${dt}', INTERVAL 1 DAY)
         ELSE end_date END AS end_date,
    is_current
FROM dim.dim_account
UNION ALL
SELECT
    account_id,
    account_code,
    account_name,
    account_level,
    parent_account_code,
    account_type,
    '${dt}' AS start_date,
    '9999-12-31' AS end_date,
    1 AS is_current
FROM ods.ods_gl_account
WHERE dt = '${dt}';
```

**DIM层必须做的处理：**
1. 维度一致性：所有财务维度全集团统一，科目表是核心主数据
2. 缓慢变化维：科目、组织架构、供应商用SCD2拉链表保留历史
3. 维度层级：科目层级、组织层级、产品层级，支持上卷下钻
4. 未知维度：关联不上的维度用-1表示，不允许NULL外键
5. 主数据管理：核心维度必须走主数据系统，不允许随意新增

### 3.3 DWD层 ETL规范
```sql
-- DWD层事实表模板（凭证明细事实表）
INSERT OVERWRITE TABLE dwd.dwd_voucher_fact PARTITION(dt='${dt}')
SELECT
    v.voucher_id,
    d.date_id,
    a.account_id,
    dept.department_id,
    c.company_id,
    v.dc_flag,
    v.amount,
    -- 借贷金额拆分
    CASE WHEN v.dc_flag = 'D' THEN v.amount ELSE 0 END AS debit_amount,
    CASE WHEN v.dc_flag = 'C' THEN v.amount ELSE 0 END AS credit_amount,
    v.summary,
    v.supplier_id,
    v.customer_id,
    -- 费用归属期间
    v.period,
    CURRENT_TIMESTAMP() AS etl_time
FROM ods.ods_finance_voucher v
LEFT JOIN dim.dim_date d ON v.voucher_date = d.date
LEFT JOIN dim.dim_account a ON v.account_code = a.account_code AND a.is_current = 1
LEFT JOIN dim.dim_department dept ON v.dept_code = dept.dept_code AND dept.is_current = 1
LEFT JOIN dim.dim_company c ON v.company_code = c.company_code AND c.is_current = 1
WHERE v.dt = '${dt}'
  AND v.voucher_status = '已过账';
```

**DWD层必须做的处理：**
1. 粒度统一：凭证明细粒度，一行一条凭证分录
2. 维度关联：关联所有维度表，维度外键不允许NULL
3. 借贷拆分：借方金额、贷方金额拆成两列，方便汇总
4. 数据过滤：只取已过账凭证，排除作废、草稿
5. 期间对齐：按会计期间归属，支持跨期调整

### 3.4 DWS层 ETL规范
```sql
-- DWS层汇总表模板（科目日汇总表）
INSERT OVERWRITE TABLE dws.dws_account_daily PARTITION(dt='${dt}')
SELECT
    date_id,
    company_id,
    account_id,
    department_id,
    SUM(debit_amount) AS total_debit,
    SUM(credit_amount) AS total_credit,
    -- 期末余额（资产+费用=借-贷；负债+权益+收入=贷-借）
    SUM(CASE WHEN a.account_type IN ('资产', '成本', '费用') 
             THEN debit_amount - credit_amount
             ELSE credit_amount - debit_amount END) AS balance,
    COUNT(DISTINCT voucher_id) AS voucher_count,
    CURRENT_TIMESTAMP() AS etl_time
FROM dwd.dwd_voucher_fact v
LEFT JOIN dim.dim_account a ON v.account_id = a.account_id
WHERE v.dt = '${dt}'
GROUP BY date_id, company_id, account_id, department_id;
```

**DWS层必须做的处理：**
1. 公共粒度：按科目天/部门天/公司月等通用维度聚合
2. 指标复用：所有公共财务指标在DWS层统一计算，ADS层直接引用
3. 层级聚合：日→月→季→年逐层聚合，复用下层数据
4. 主题划分：按总账、应收、应付、库存、费用、成本主题域划分

### 3.5 ADS层 ETL规范
```sql
-- ADS层视图模板（利润表）
CREATE VIEW ads.ads_income_statement AS
SELECT
    stat_period,
    company_id,
    -- 收入类
    SUM(CASE WHEN account_type = '收入' THEN balance ELSE 0 END) AS total_revenue,
    -- 成本类
    SUM(CASE WHEN account_type = '成本' THEN balance ELSE 0 END) AS total_cost,
    -- 毛利
    SUM(CASE WHEN account_type = '收入' THEN balance ELSE 0 END)
    - SUM(CASE WHEN account_type = '成本' THEN balance ELSE 0 END) AS gross_profit,
    -- 费用类
    SUM(CASE WHEN account_type = '费用' THEN balance ELSE 0 END) AS total_expense,
    -- 净利润
    SUM(CASE WHEN account_type IN ('收入', '收益') THEN balance ELSE 0 END)
    - SUM(CASE WHEN account_type IN ('成本', '费用', '损失') THEN balance ELSE 0 END) AS net_profit
FROM dws.dws_account_monthly
GROUP BY stat_period, company_id;
```

**ADS层必须遵守的规则：**
1. 只从DWS取数，禁止直接从DWD/DIM关联
2. 优先用视图，保证数据一致性
3. 一个报表对应一个ADS视图（资产负债表/利润表/现金流量表）
4. 字段名和财务报表标准字段完全对应

## 四、SQL兼容性说明（MySQL → Hive/Oracle）

本地MySQL SQL迁移到生产环境只需要修改以下几点：

| MySQL语法 | Hive语法 | Oracle语法 | 说明 |
|----------|---------|-----------|------|
| AUTO_INCREMENT | row_number()生成 | SEQUENCE | 主键生成方式 |
| DATE_FORMAT() | date_format() | TO_CHAR() | 时间格式化 |
| IFNULL() | nvl() / coalesce() | NVL() / NVL2() | 空值处理 |
| NOW() | current_timestamp() | SYSDATE | 当前时间 |
| STR_TO_DATE() | to_date() | TO_DATE() | 时间转换 |
| GROUP_CONCAT() | collect_list/collect_set | LISTAGG() | 字符串聚合 |
| DECIMAL(15,2) | DECIMAL(15,2) | NUMBER(15,2) | 金额类型 |
| INSERT OVERWRITE | INSERT OVERWRITE + 分区 | MERGE / INSERT /*+ APPEND */ | 覆盖写入 |
| 窗口函数 | 支持 | 支持 | 基本一致 |

> 整体兼容性90%以上，核心财务逻辑不需要修改，只需要调整少量函数语法。
