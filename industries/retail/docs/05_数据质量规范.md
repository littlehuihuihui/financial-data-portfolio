# 零售财务 · 数据质量规范 v3.1

> 财务数据零差错原则，6维度质量监控体系，全链路可追溯可审计

---

## 一、数据质量6维度体系

### 1.1 完整性（Completeness）
> 数据是否齐全，有没有缺失

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 | 处理方式 |
|---------|---------|---------|---------|---------|
| 凭证数据 | 每日凭证条数与源系统对比 | 差异率 = 0% | P0 紧急 | 立即重跑，对账差异必须为0 |
| 科目维度 | 科目表是否完整，有无缺失科目 | 缺失数 = 0 | P0 紧急 | 补全主数据，重新关联 |
| 销售流水 | POS流水条数与源系统对比 | 差异率 < 0.01% | P1 高 | 小时级补数，日结前必须一致 |
| 库存数据 | 库存SKU数与WMS对比 | 差异率 = 0% | P0 紧急 | 盘点对账，差异必须查清 |
| 维度表 | 维度表主键非空率 | 非空率 = 100% | P1 高 | 补全未知维度默认值 |

### 1.2 准确性（Accuracy）
> 数据是否正确，有没有错误

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 | 处理方式 |
|---------|---------|---------|---------|---------|
| **借贷平衡** | 每张凭证借方合计 = 贷方合计 | 差异 = 0 | P0 紧急 | 凭证作废，退回源系统修正 |
| **金额非负** | 所有金额字段不能为负数（红冲除外） | 异常率 = 0% | P0 紧急 | 标记异常，人工审核 |
| **余额校验** | 科目期末余额 = 期初 + 本期发生 | 差异 = 0 | P0 紧急 | 重新计算，追溯错误凭证 |
| **对账一致** | 数仓数据与ERP源系统对账 | 差异率 = 0% | P0 紧急 | 逐笔核对，找出差异原因 |
| **库存非负** | 库存数量不能为负 | 异常率 = 0% | P1 高 | 查明原因，调整库存 |

### 1.3 一致性（Consistency）
> 同一指标在不同地方是否一致

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 | 处理方式 |
|---------|---------|---------|---------|---------|
| 指标口径一致性 | 同一指标在不同看板数值一致 | 差异 = 0 | P1 高 | 统一口径，修改错误计算逻辑 |
| 维度一致性 | 同一维度在不同事实表编码一致 | 匹配率 = 100% | P1 高 | 统一维度编码主数据 |
| 科目层级一致性 | 上下级科目余额汇总一致 | 差异 = 0 | P0 紧急 | 修正科目层级关系 |
| 跨表一致性 | 订单金额与凭证金额一致 | 差异率 < 0.01% | P1 高 | 逐笔核对，找出差异单据 |
| 期间一致性 | 所有数据按会计期间归属正确 | 错误率 = 0% | P1 高 | 调整期间归属 |

### 1.4 及时性（Timeliness）
> 数据是否按时产出

| 数据层级 | 产出时间要求 | 延迟告警 | 业务影响 |
|---------|-----------|---------|---------|
| ODS层 | 每日凌晨6:00前完成同步 | 延迟>30分钟告警 | 影响后续所有ETL |
| DWD层 | 每日凌晨7:00前完成 | 延迟>30分钟告警 | 影响DWS汇总 |
| DWS层 | 每日凌晨8:00前完成 | 延迟>30分钟告警 | 影响早会看板 |
| ADS层/看板 | 每日上午9:00前可用 | 延迟>1小时告警 | 经营日报延迟 |
| 月结报表 | 每月5号前完成上月月结 | 延迟>1天告警 | 财务结账延迟 |

### 1.5 有效性（Validity）
> 数据格式、类型、范围是否合法

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 |
|---------|---------|---------|---------|
| 日期格式 | 日期字段格式合法，在合理范围内 | 异常率 = 0% | P2 中 |
| 金额格式 | 金额字段为数字，精度保留2位小数 | 异常率 = 0% | P2 中 |
| 凭证状态 | 状态值在枚举范围内（已过账/作废/草稿） | 异常率 = 0% | P1 高 |
| 科目编码 | 科目编码符合编码规则，在科目表中存在 | 异常率 = 0% | P1 高 |
| 敏感数据 | 银行账号、客户信息已脱敏 | 脱敏率 = 100% | P1 高 |

### 1.6 唯一性（Uniqueness）
> 数据是否重复

| 监控对象 | 监控规则 | 阈值要求 | 告警级别 |
|---------|---------|---------|---------|
| 凭证号 | 同一凭证号+行号唯一 | 重复率 = 0% | P0 紧急 |
| 订单号 | 同一订单号唯一 | 重复率 = 0% | P1 高 |
| 维度主键 | 维度表主键唯一 | 重复率 = 0% | P1 高 |
| 银行流水 | 同一流水号唯一 | 重复率 = 0% | P2 中 |

## 二、ERP数据源接入规范（整合到数仓体系）

### 2.1 核心源系统清单

| 源系统 | 系统类型 | 数据库 | 核心数据 | 接入方式 | 同步频率 | 质量要求 |
|-------|---------|--------|---------|---------|---------|---------|
| **ERP系统** | 核心财务 | Oracle/SQL Server | 凭证、科目、往来、总账、报表 | DataX离线同步 | T+1 凌晨日结后 | 对账差异=0，借贷平衡 |
| **POS/收银系统** | 前端销售 | MySQL | 销售流水、收银、退款、折扣 | DataX离线 + CDC | T+1 + 小时级 | 笔数一致，金额一致 |
| **OMS订单系统** | 电商订单 | MySQL | 订单、发货、退款、售后 | DataX + Canal | T+1 + 准实时 | 订单状态流转正确 |
| **WMS仓储系统** | 库存管理 | MySQL | 出入库、库存、盘点、库位 | API/DataX | T+1 凌晨 | 库存非负，账实一致 |
| **采购系统** | 供应链 | MySQL | 采购订单、入库、供应商、应付 | DataX离线 | T+1 凌晨 | 采购入库与应付一致 |
| **HR系统** | 人事薪酬 | MySQL | 人员、薪资、组织架构 | 手动/API | 每月月结 | 组织架构与部门维度一致 |
| **费用报销系统** | 费用管理 | MySQL | 报销单、费用明细、审批 | API接口 | T+1 | 费用科目映射正确 |
| **银行流水** | 资金管理 | Excel/银企直连 | 收付款、余额、流水 | 银企直连/手动导入 | 每日 | 余额一致，借贷方向正确 |

### 2.2 ODS层数据接入质量校验

```sql
-- ODS层凭证数据质量校验SQL示例
SELECT 
    '借贷不平衡' AS check_type,
    COUNT(*) AS error_count
FROM ods_finance_voucher
WHERE dt = '${dt}'
GROUP BY voucher_no
HAVING SUM(CASE WHEN dc_flag='D' THEN amount ELSE -amount END) <> 0;

-- 与源系统对账校验
SELECT 
    '凭证条数差异' AS check_type,
    (SELECT COUNT(*) FROM ods_finance_voucher WHERE dt='${dt}') 
    - (SELECT COUNT(*) FROM source_erp.voucher WHERE voucher_date='${dt}')
    AS diff_count;
```

## 三、质量问题处理流程

### 3.1 告警分级响应
- **P0 紧急（财务数据错误）**：30分钟内响应，立即暂停下游任务，排查修复
- **P1 高（数据延迟/少量异常）**：2小时内响应，当日修复
- **P2 中（格式问题/非核心数据）**：1个工作日内响应，下次迭代修复
- **P3 低（优化建议）**：排期处理

### 3.2 问题处理SOP
1. **发现告警**：质量监控规则自动触发，发送告警通知
2. **影响评估**：评估影响范围，是否需要暂停下游任务
3. **定位根因**：从源系统→ODS→DWD→DWS逐层排查
4. **修复方案**：确定修复方式（重跑/补数/修正逻辑）
5. **执行修复**：执行修复，重新运行ETL
6. **验证结果**：质量校验通过，恢复下游任务
7. **复盘总结**：记录问题，优化监控规则，避免再发

## 四、财务数据审计与留痕

### 4.1 审计要求
- 所有数据变更必须有记录，支持追溯到原始凭证
- 报表数据支持钻取到明细，再钻取到原始凭证
- 所有ETL操作留日志，谁在什么时候改了什么
- 历史数据不可随意修改，修改必须走审批流程

### 4.2 数据版本管理
- 月结后数据冻结，不允许修改
- 确需调整的，走财务调整凭证，不直接改历史数据
- 保留每个版本的快照，支持对比差异
