# 第 07 章 · 元数据、血缘与知识检索

## 1. 本章目标

1. 区分：业务元数据、技术元数据、操作元数据。  
2. 理解表级血缘与字段级血缘的用途差异。  
3. 会用「影响分析」评估改一个字段会炸哪些看板。  
4. 把作品集的图谱/搜索理解为元数据应用，而不是装饰。

---

## 2. 理论：元数据是数仓的说明书

| 类型 | 例子 |
|------|------|
| 业务元数据 | 指标口径、业务过程、主题域 |
| 技术元数据 | 表结构、分区、DDL、视图定义 |
| 操作元数据 | 调度日志、DQ 结果、行数 |

没有元数据的数仓 = 没有图纸的厂房。

---

## 3. 血缘

### 3.1 表级血缘

回答：这张表从哪来、到哪去。用于：排障下钻、变更影响、新人 onboarding。

### 3.2 字段级血缘

回答：`dau` 字段由哪些源字段算出。用于：口径争议、合规。

### 3.3 完整性

血缘缺失常见原因：手工 SQL 未登记、视图嵌套过深、占位符（如 lineage 写 `"DWS"`）。治理手段：从仓库解析 + 强制登记 + 全景校验「ADS 必有上游」。

---

## 4. 检索与知识图谱

- **搜索**：精确命中表/字段/问题  
- **平台图谱**：模块与能力如何互联（导航型知识）  
- **数仓图**：表依赖（结构型知识）  

面试表述：图谱是加速理解与定位的 **元数据产品**，不替代数仓存储。
