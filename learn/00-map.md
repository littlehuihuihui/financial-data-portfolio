## 2. 核心理论：为什么要建数仓

### 2.1 业务库不是分析库

业务系统（ERP、OMS、MES、日志服务）为 **交易与操作** 优化：高并发写入、强一致事务、在线接口。分析场景要的是：

- **跨系统整合**（订单 + 支付 + 库存 + 埋点）  
- **历史可回放**（去年同日对比）  
- **口径稳定**（「收入」全公司同一句话）  
- **可审计**（这个数怎么算出来的）  
- **查询隔离**（分析别拖垮交易库）

直接在业务库上写「大宽 SQL」短期能出数，长期会出现：口径分叉、夜间跑挂、改字段全挂、新人无法接手。

### 2.2 数仓解决的四类问题

| 问题 | 没有数仓时 | 有数仓时 |
|------|------------|----------|
| 口径 | 每人一套 SQL | 指标字典 + ADS/DWS 固化 |
| 整合 | 临时 Join 多库 | ODS 汇流后统一加工 |
| 性能 | 扫生产大表 | 汇总层预聚合 |
| 协作 | 口口相传 | 分层契约 + 血缘 + 调度 |

### 2.3 「贴源 → 明细 → 汇总 → 应用」不是形式主义

分层的本质是 **把不同变化频率、不同消费方式的数据分开管理**：

- 源系统字段天天变 → 用 ODS 隔离冲击  
- 分析要稳定粒度 → 用 DWD 声明「一行是什么」  
- 看板要秒开 → 用 DWS 预聚合  
- 业务方要「好懂的指标」→ 用 ADS 封装  

下一章展开五层定义与 Kimball 四步；第 03 章展开 **层与层之间具体怎么算**。

## 3. 本教材怎么学（重要）

### 3.1 错误用法

- 只点「实验台」链接，当成作品集导览。  
- 只背 ODS/DWD 缩写，不会写出层间 SQL 骨架。  
- 跳过粒度声明，直接谈宽表字段。

### 3.2 正确用法

每章固定节奏：

1. **理论**：概念、原则、反例、面试标准答法  
2. **计算范式**：伪 SQL / 变换模板（能默写骨架）  
3. **作品集实例**：互联网主线表名，零售/制造对照  
4. **实操作业**：你必须动手写出或对照验证  
5. **文末实验台**：打开页面核对，而不是从页面开始学  

### 3.3 建议学习顺序

`00 导论 → 01 分层与建模 → 02 粒度与 ER → 03 层间计算（核心）→ 04 ETL 工程 → 05 口径与看板 → 06 分析方法论 → 07 元数据血缘 → 08 端到端作业 → R 总复习`

其中 **03 是全书最硬的一章**，请预留完整时间。

## 4. 三行业作为「同一范式的三套题库」

| 行业 | 训练重点 | 代表主题 |
|------|----------|----------|
| 互联网 OTT（主线） | 行为日志、日活、漏斗、留存 | Launcher / 点播 / 订购 |
| 零售财务 | 金额口径、单据状态、月结节奏 | 订单/费用/库存/预算 |
| 制造业 | 工单粒度、质量、设备效率 | 产量/良率/OEE |

你学的是 **同一套分层与计算纪律**；换行业只是换业务过程与度量。

## 5. 作品集在本教材中的角色

作品集已经实现了：

- 五层对象与全景可视化  
- ER / 字典 / ETL 血缘面板  
- 指标口径与看板  
- 方法论场景  

它是 **已建好的参考实现 + 实验台**，不是「点一点就会」的替代教材。真实工作中你仍要会：声明粒度、写层间 SQL、定调度与口径、做异常下钻。
