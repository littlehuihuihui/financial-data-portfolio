# 工程专题 E2 · 迟到数据、回刷与时间语义

## 1. 两种时间

| 时间 | 含义 | 本仓库常见列 |
|------|------|----------------|
| 事件时间 | 业务真实发生 | `event_time` / `event_date` / `op_date` |
| 入库时间 | 进入 ODS 的时刻 | 作品集多数字段未强制；靶场用批次 `etl_batch_id` |

> **证据**：开机 ODS 使用 `event_time`,`event_date`（`ott_ddl.sql`）。  
> 若按「入库日」分区却按「事件日」出 DAU，迟到日志会进错日或漏计。

## 2. 迟到如何处理（通用策略）

1. **水位线**：事件时间 < now()-延迟 才关闭分区。  
2. **允许重跑窗口**：例如 T+1~T+3 可回刷近 N 日 DWD/DWS。  
3. **幂等覆盖**：按业务日 `DELETE`/`INSERT` 或按主键 upsert（见 E3）。

## 3. 与 OTT 灌数范围的关系

> **证据**：`seed_ott.py` 文件头：DWS 覆盖 `2026-04-16~07-15`；原始日志 **仅** `LOG_DAYS` 近 3 天。  

含义：看板若下钻到「三天前以前」的明细日志，**可能没有 ODS/DWD 日志行**——这是演示数据策略，写进设计文档时要当作已知限制，不能假装「全历史明细都在」。

## 4. 回刷检查单

- [ ] 回刷哪一层？（通常 DWD→DWS；ADS 为视图则自动变）  
- [ ] 业务日闭区间？  
- [ ] 下游依赖是否重跑？（漏斗、留存常依赖活跃日表）  
- [ ] 口径变更 vs 补数：是否需要发变更说明？（见第 05 章）
