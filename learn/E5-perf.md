# 工程专题 E5 · 分区裁剪、倾斜与性能意识

> 本仓库 MySQL 演示表多用索引（如 `KEY idx_mac_date`），**不等同** Hive/Iceberg 分区表。下列为通用中级概念 + 对本仓库的映射。

## 1. 分区裁剪

只扫描与查询谓词匹配的分区/目录，避免全表。

对本仓库：

- 查询务必带 `event_date` / `snapshot_date` / `op_date` 等（见各表 DDL）  
- ADS 视图若无日期过滤，会扫可见的全部 DWS 历史（演示库三个月活跃）

## 2. 数据倾斜

少数 key 占绝大多数流量（如头部剧集、头部门店），导致聚合变慢或内存爆。

缓解思路：盐缀、预聚合分层、单独拆头部、两阶段聚合。

## 3. 练习

1. 在 `ott_ddl.sql` 找出 `ods_log_vod_di` 上与日期相关的 KEY。  
2. 解释：为何 `v_dau_overview` 按日 GROUP BY 仍可能随历史变长而变慢。  
3. 举一个「倾斜」业务例子（OTT 或零售）。
