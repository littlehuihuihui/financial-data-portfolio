# 第 08 章 · 端到端实战：从需求到 ADS 的完整设计作业

## 1. 本章目标

独立完成一份 **可评审的主题域设计包**（可不建生产表，但须达到同事能按文档开工）。

主线推荐题 A；题 B/C 为对照选修。

---

## 2. 作业背景（任选一题）

**题 A（推荐，互联网）**：新增「有效播放完播率」主题，服务内容运营周会。  
**题 B（零售，对照）**：新增「门店毛利异常监控」主题。  
**题 C（制造，对照）**：新增「产线小时产出与停机」主题。

题 A 约束（防幻觉）：

- 点播相关真表优先复用：`ods_log_vod_di` / `dwd_vod_play_di` / `dws_content_episode_play_1d`（均见 `ott_ddl.sql`）  
- 完播相关真字段：`is_finish`、`complete_rate`（见 `dwd_vod_play_di`）  
- 新 ADS 视图名可自拟，但 FROM 必须是 DWS/DWD（遵守 `04_ott_ads_views.sql` 纪律）

---

## 3. 交付物清单（必须全部有）

1. 业务过程与成功标准  
2. Kimball 四步（粒度可测试）  
3. 表清单：ODS/DIM/DWD/DWS/ADS（复用须写「复用 + 路径」）  
4. 层间计算：每跳伪 SQL 或算法（列名须能在 DDL grep 到，或明确标注「拟新增列」）  
5. 调度依赖草图 + SLA  
6. 指标口径四件套（≥2 个）  
7. DQ 门禁（每层≥1）  
8. 看板草图：3 个图表/KPI  
9. 风险与开放问题（须包含：与 `seed_ott.py` 近 3 天日志限制是否冲突）

---

## 4. 评分标准（自评）

| 项 | 不合格 | 合格 | 优秀 |
|----|--------|------|------|
| 粒度 | 含糊 | 可执行 | 带唯一性/可加性论证 |
| 分层 | 混乱跨层 | 符合规范 | 说明复用与例外 |
| 计算 | 只有概念 | 有骨架 SQL | 含去重/维关联/勾稽 |
| 口径 | 口头 | 四件套 | 含变更影响 |
| 证据 | 表名臆造 | 均可 grep | 引用 COMMENT/视图原文 |
| 可落地 | 无法交给工程 | 可开工 | 含回刷与失败策略 |
