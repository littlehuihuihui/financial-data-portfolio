# 工程专题 E7 · 数据契约模板

## 1. 为什么要契约

上下游（采集、数仓、看板、分析）对「字段、粒度、SLA、空值」理解不一致时，口径事故会重复发生。

## 2. 最小模板（可复制）

```markdown
# 契约：<主题域 / 表或接口名>
- 责任人：数据 owner / 业务 owner
- 消费者：看板 X / 作业 Y
- 粒度：一行 = …
- 主键 / 业务键：
- 分区或业务日列：
- 字段清单：名 / 类型 / 空值语义 / 枚举
- 刷新：T+1 几点可用 / 失败策略
- 兼容性：禁止无公告删列；改口径须版本号
- DQ：上线门禁列表
- 证据链接：DDL 路径、视图路径、监控文档段落
```

## 3. 对本仓库的实例化（示例）

**对象**：`dws_act_user_active_1d` → `v_dau_overview`  

- 粒度：日×mac（DWS）；日切片 UV（ADS）  
- 证据：`ott_ddl.sql`；`04_ott_ads_views.sql`  
- SLA（演示）：以种子数据为准；生产需另定  
- 破坏示例：ADS 改读 ODS——契约违规
