# 第 04 章 · ETL 工程：调度、依赖、质量门禁与排障

## 1. 本章目标

1. 设计一条主题域的 **调度依赖图**（谁先谁后、失败怎么办）。  
2. 区分：批处理 T+1、微批、流式、视图读时计算。  
3. 写出最小可行的 DQ（数据质量）门禁集。  
4. 按「ADS→DWS→DWD→ODS」做一次标准排障演练。

---

## 2. 理论：ETL 不只是 SQL

ETL/ELT 工程包含：

| 组件 | 职责 |
|------|------|
| 作业（Job） | 一次可调度的加工单元 |
| 依赖 | 上游分区就绪才能跑 |
| 调度器 | 时间触发 / 事件触发 |
| 质量门禁 | 不通过则阻断下游或告警 |
| 血缘 | A→B 的代码与口径落点 |
| 重跑与回补 | 幂等、区间重刷 |

作品集 ETL 面板把「调度策略 + 表级变换」可视化，便于对照理论。

---

## 3. 调度设计

### 3.1 典型日链路（T+1）

```
02:00  ODS 灌入昨日分区
03:30  DIM 缓缓更新 / 全量校验
05:00  DWD 明细
06:30  DWS 汇总
07:00  DQ 门禁
07:30  看板可用（ADS 视图自动读到新 DWS）
```

### 3.2 依赖原则

- 同业务日：OTT 用 `event_date` / `snapshot_date` / `op_date` 等列对齐（**不是**统一叫 `dt`——以各表 DDL 为准）  
- 跨日：留存 D7 依赖队列定义日与偏移（见 `dws_user_retention_1d`）  
- 维表：OTT 当前态维；属性大变需评估是否回刷事实上的退化属性（见 E1/E2）

### 3.3 SLA 与业务承诺

向业务承诺「早 9 点看昨天」前，先算清：最坏耗时 + 失败重试窗口。不能用 ADS「实时」忽悠成「业务库实时」。

---

## 4. 表级变换（A→B）你要记录什么

每条边建议具备：

- from_table / to_table / 层级  
- schedule / engine（sql/python/view）  
- grain（输出粒度）  
- computation（人话）  
- code_path / 入口  
- sql_excerpt（可检索）

这是排障与交接的最小元数据；作品集 `etl-lineage-data` 即此结构的示例。

---

## 5. 数据质量门禁（实用最小集）

| 层级 | 检查 |
|------|------|
| ODS | 行数、空主键、时间合法 |
| DWD | 维关联成功率、去重后行数、枚举合法 |
| DWS | 与 DWD 勾稽（如 SUM 明细=汇总）、异常 0 值 |
| ADS | 核心 KPI 波动告警、空结果 |

门禁失败策略：阻断 / 仅告警 / 降级用昨日数据——必须书面约定。

---

## 6. 排障SOP（背下来）

1. 看板哪个指标、哪个时间、哪个维度切片？  
2. 对口径：是否定义变更？  
3. ADS 视图定义是否指向正确 DWS？  
4. DWS 分区是否产出？行数是否异常？  
5. DWD/ODS 是否缺口、重复、维键大量 -1？  
6. 调度日志：哪步失败、是否重跑成功？  
7. 修复后：回补分区 + 回归看板 + 记变更
