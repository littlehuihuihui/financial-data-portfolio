## 1. 本章目标

1. 掌握「业务问题 → 可验证假设 → 所需指标/表 → 结论与动作」闭环。  
2. 理解结构化分析框架（如零售六层）如何降低漏检。  
3. 能把方法（漏斗、帕累托、队列留存）映射到正确粒度的表。  
4. 在作品集方法论页完成一次「场景—表」对照。

---

## 2. 理论：分析不是看图说话

好的分析交付物包含：

1. **问题定义**：可证伪（「转化下降」要落到哪一步、哪渠道、哪时段）  
2. **假设树**：并列假设，可逐条排除  
3. **证据**：指标 + 维度下钻 + 对照实验/同期  
4. **根因与影响**：量化「若不修损失多少」  
5. **动作与复盘**：谁在何时做什么，如何验收  

数仓的价值：让证据可复现；方法论的价值：让步骤可复制。

---

## 3. 框架示例：零售六层（可迁移）

| 层 | 问题类型 | 数据侧常见落点 |
|----|----------|----------------|
| L1 概览 | 是否异常 | ADS 经营概况 |
| L2 结构 | 哪里异常 | 维拆解 DWS |
| L3 驱动 | 为什么 | 明细 DWD + 口径 |
| L4 风险 | 会怎样 | 现金流/预算等 |
| L5 动作 | 怎么办 | 结论与责任人 |
| L6 方法库 | 用什么分析技术 | 工具箱，不替代 L1–L5 |

互联网场景页、制造场景页是同一思想的「主题化」：留存、漏斗、质量、OEE。

---

## 4. 方法与表粒度匹配（关键）

| 方法 | 需要的粒度 | 错误用法 |
|------|------------|----------|
| 漏斗 | 步骤事件或步骤日汇总 | 用月汇总硬掰步骤 |
| 留存队列 | 首次事件日 + 后续活跃 | 只用 DAU 曲线「感觉」 |
| 帕累托 | 可排序的对象贡献 | 对象口径不一致 |
| 杜邦 | 财务科目汇总 | 直接从 ODS 凭证乱加 |
