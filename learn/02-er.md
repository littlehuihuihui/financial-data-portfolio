# 第 02 章 · 维度建模深化：粒度、星型/雪花与 ER

## 1. 本章目标

1. 能独立审查一张事实表的粒度是否「可加、可复现、可关联」。  
2. 画清星型与雪花的适用边界。  
3. 用 ER 图 + 数据字典完成「实体—关系—字段」三级阅读。  
4. 写出维表变更时对事实表与汇总层的影响清单。

---

## 2. 粒度工程（比背定义更重要）

### 2.1 粒度测试三问

对任意候选事实表，问：

1. **唯一性**：同一业务事件会不会插出两行？主键/业务键如何防重？  
2. **可加性**：把两行的度量相加，业务含义是否仍正确？  
3. **下钻性**：从 DWS 回到 DWD，能否解释差异？

若三问有一问答不清，先别建 DWS。

### 2.2 常见粒度错误

| 错误 | 后果 | 纠正 |
|------|------|------|
| 把日汇总当明细 | 无法做漏斗/路径 | 保留 DWD 事件表 |
| 把多业务过程塞一张事实 | 大量空字段、口径混乱 | 拆主题域 |
| 维退化失控 | 事实表膨胀 | 抽出 DIM |
| 比率进 DWD | 再汇总必错 | 比率放 ADS 或汇总后算 |

### 2.3 事务事实 vs 快照事实 vs 累计快照

- **事务事实**：一笔订购、一次播放——可追加  
- **周期快照**：每日库存结存、每日设备状态  
- **累计快照**：工单从创建到关闭的里程碑节点  

制造工单、零售库存特别容易混用，建模时必须写进 COMMENT。

## 3. 星型与雪花

### 3.1 星型（Star）

事实表居中，一圈维表。优点：好懂、好讲、查询路径短。适合作品集讲解与多数看板。

### 3.2 雪花（Snowflake）

维表继续规范化（内容→剧集→CP；地市→省）。优点：减少维冗余、主数据更干净；代价：Join 多、对分析师不友好。

**实用建议**：对分析消费，可在 DWD/DWS **冗余关键维属性**（反雪花），但 DIM 层仍可保持规范化供主数据治理。

### 3.3 一致性维度

跨「活跃」「订购」「收入」主题，日期维、设备维必须一致；否则 DAU 与付费用户对不上号。

## 4. ER 图怎么读、怎么用

1. 找矩形：实体（表）  
2. 找连线：1:n / n:n（中间表）  
3. 标出事实实体 vs 维实体  
4. 打开数据字典核：PK、FK、字段业务含义、表 purpose  

作品集中：ER 页解决结构，字典解决语义，全景解决分层位置——三者要交叉看同一张表。

---

## 5. 维变与影响分析（实用）

当业务说「渠道要改成新编码」：

1. ODS：源是否已切码  
2. DIM：映射表/代理键是否重建  
3. DWD：历史行是否重刷  
4. DWS/ADS：是否需回灌区间  
5. 口径文档：是否发变更说明  

没有影响清单的改维，是线上事故的温床。

## 6. 作品集实例

互联网：行为事实挂 `dim_device` / 内容维 / `dim_date`；雪花可见省份—地市级维。  
零售：订单事实挂门店/品牌/品类。  
制造：工单/质检挂产线/物料/供应商。

## 7. 练习

1. 为「收银台漏斗」声明 DWD 与 DWS 两种粒度（各一句话）。  
2. 判断：毛利率应存在 DWD 还是 ADS？为什么？  
3. 在字典中任选一张 `dim_*`，列出 1 个 PK + 2 个属性字段的业务含义。  
4. 写一份「门店维新增字段」的影响清单（至少覆盖 DIM/DWD/DWS/看板）。

:::answer 参考要点
1. DWD≈漏斗步骤事件；DWS≈日×步骤计数。  
2. ADS（或 DWS 算分子分母后 ADS 相除）。  
4. 需评估历史回刷与看板字段映射。
:::
