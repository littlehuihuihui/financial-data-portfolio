# 数仓分层全景图 · 视觉美化改造方案

> 文档版本：v1.0 · 2026-08-10  
> 组件：`dw-architecture.js` + `dw-architecture.css` + `dw-architecture-data.js`  
> 页面：`pages/architecture.html#dw-architecture-section`

---

## 1. 现状问题诊断

### 1.1 已确认的 Bug（优先修复）

| 问题 | 现象 | 原因 |
|------|------|------|
| **表卡片文字无样式** | 中文用途/英文表名大小不分、间距乱 | JS 输出 `dw-arch-table-name-cn` / `dw-arch-table-name-en`，CSS 只定义了 `dw-arch-table-name` / `dw-arch-table-purpose` |
| **连线与缩放不同步** | 缩放/拖拽后连线偏移或错位 | SVG 尺寸取外层 `canvas` 视口，路径坐标用 `getBoundingClientRect`；`inner` 有 transform 时基准不一致 |
| **连线全量渲染** | 互联网 50+ 表、100+ 流向时满屏「意大利面」 | 默认绘制全部 `flows`，仅 8px 错开不足 |

### 1.2 布局与信息架构问题

```
┌─ 控制栏（行业切换 + 搜索 + 缩放 + 导出 + 重置）─┐
├─ 筛选栏（5 层 checkbox + 表/视图）─────────────────┤
├─ 图例栏（6 项 + 提示）───────────────────────────┤  ← 三层 chrome 占 150px+，真正的图被挤下去
└─ 画布（5 列 × 200px 窄泳道 × N 张卡片）───────────┘
```

| 问题 | 说明 |
|------|------|
| **Chrome 过重** | 控制 + 筛选 + 图例三行，首屏几乎看不到泳道 |
| **泳道过窄** | 固定 `200px`，表名换行、卡片等高参差不齐 |
| **DIM 列语义弱** | 横向五列等权，DIM 与 ODS 同宽，但 DIM 是「挂载维度」而非主流程下一跳，用户看不懂为何夹在中间 |
| **纵向过高** | 互联网 DIM 层 18 张表竖排，单列高度可超 2000px，横向滚动 + 纵向滚动画布体验差 |
| **与知识图谱重复** | 同页下方有力导向图，全景图的「全网血缘」价值被稀释 |
| **行业切换多余** | 零售架构页仍显示三行业 Tab，易误切且数据与当前页不一致 |
| **ADS 用红色 `#ef4444`** | 与危险/告警色冲突，应用层不像「出口」而像「异常」 |

### 1.3 美学问题

- 表卡片：扁平灰框 + 左边线，缺少层级色带与景深
- 泳道：无列背景区分，五层靠左边框 4px 色条，远处难辨
- 连线：半透明蓝线堆叠，无「层间总线」概念
- 控件：Emoji（📷🔍）与全站商务深色风不统一
- 动效：全部高亮连线流动动画，选中一张表时仍显乱

## 2. 美化目标

1. **一眼读懂**：ODS →（DIM 辅助）→ DWD → DWS → ADS 主链路清晰，DIM 不抢主流程。
2. **默认干净**：初始状态少线、少噪；交互时才展示血缘。
3. **卡片可读**：用途为主标题、表名 monospace 次要，层色可识别。
4. **首屏有图**：工具栏压缩为一行，画布默认高度内能看到五层轮廓。
5. **与字典/图谱分工**：全景图 = 分层 + 主链路；图谱 = 复杂网；字典 = 字段口径。

---

## 3. 推荐布局：「主流程四列 + DIM 侧栏」

### 3.1 结构示意

```
                    ┌─ DIM 维度（可折叠侧栏 180px）─┐
                    │ dim_date                      │
                    │ dim_brand                     │
                    │ …                             │
┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐          │
│ ODS  │ → │ DWD  │ → │ DWS  │ → │ ADS  │          │
│ 8表  │   │ 3表  │   │ 4表  │   │ 9视图│          │
│ ▢▢▢  │   │ ▢▢▢  │   │ ▢▢▢  │   │ ▢▢▢  │          │
└──────┘   └──────┘   └──────┘   └──────┘          │
     ╲___________虚线关联 DIM___________╱           │
└───────────────────────────────────────────────────┘
         ↑ 层间「总线」竖线 + 水平分支，而非张张卡直连
```

**改动要点：**

- 主画布 **4 列**（ODS / DWD / DWS / ADS），列宽 `minmax(220px, 1fr)`。
- **DIM** 改为左侧可折叠侧栏，或顶部「维度层」横条（表少时）。
- 列背景：每层 `linear-gradient(180deg, layerColor@8%, transparent)` 宽色带。
- 列顶固定 **层头卡片**：层名 + 全称 + 表数 + 一句 desc（sticky within column）。

### 3.2 表卡片分组（列内）

按 `category` 分组折叠，避免 18 张 DIM 表竖排长列：

```
DIM · 设备维度 (3)  ▼
  dim_device
  dim_device_type
DIM · 内容维度 (5)  ▶
```

零售/互联网数据里已有 `category` 字段，可直接用。

## 4. 连线策略：「默认隐藏，选中发光」

| 模式 | 行为 |
|------|------|
| **默认** | 不画表级连线；仅画层间 3 条主箭头（ODS→DWD→DWS→ADS） |
| **Hover 表** | 画该表 1-hop 上下游（实线 ETL + 虚线 DIM），最多 ~6 条 |
| **选中表** | 全链路高亮 + 流动动画；其余表/线 `opacity: 0.2` |
| **「显示全部血缘」开关** | 高级用户手动打开，才画全量 bezier（现状） |

实现：给 `drawFlows(mode)` 增加 `mode: 'layer' | 'focus' | 'full'`，默认 `'layer'`。

**层间总线算法（focus 模式）：**

```
从 from 列右边缘中点 → 水平到列间中点 → 垂直到 to 卡片 Y → 水平进 to 列
```

比 card-to-card 直接贝zier 交叉少 70% 以上。

## 5. 视觉规范（Token 对齐）

### 5.1 分层配色（调整 ADS）

| 层 | 现色 | 建议色 | 语义 |
|----|------|--------|------|
| ODS | `#6b7280` | `#64748b` | 贴源灰 |
| DIM | `#3b82f6` | `#6366f1` | 维度靛 |
| DWD | `#10b981` | `#14b8a6` | 明细 Teal |
| DWS | `#f59e0b` | `#f59e0b` | 汇总 Amber（保留） |
| ADS | `#ef4444` ❌ | `#8b5cf6` 或 `#22d3ee` | 应用出口紫/青，避免告警红 |

### 5.2 表卡片

```css
.dw-arch-table-card {
  border-radius: 10px;
  background: linear-gradient(135deg, rgba(20,27,45,0.95), rgba(13,18,32,0.9));
  border: 1px solid rgba(255,255,255,0.06);
  border-left: 3px solid var(--layer-color);
  padding: 10px 12px;
}
.dw-arch-table-name-cn {  /* 修复：与 JS 对齐 */
  font-size: 13px;
  font-weight: 600;
  color: var(--color-text-primary);
  line-height: 1.35;
}
.dw-arch-table-name-en {
  font-family: var(--font-mono);
  font-size: 11px;
  color: var(--color-text-secondary);
  margin-top: 2px;
}
```

选中态：层色外发光 `box-shadow: 0 0 0 1px var(--layer-color), 0 4px 20px layerColor@25%`。

## 6. 交互优化

| 项 | 建议 |
|----|------|
| 单击表 | 右侧 **内嵌详情面板**（400px），替代全屏 fixed sidebar，画布不被遮满 |
| 双击表 | 跳转数据字典 `#dict/{table}`（与字典 Master-Detail 联动） |
| 列折叠 | 点击层头折叠该列所有表，只留层头 + 表数 |
| 迷你地图 | 画布右下角 120×80 缩略导航（内容超出视口时显示） |
| 首次进入 | `fitView()` 自动缩放到五列完整可见 |
| 空筛选 | 层全关时提示「至少保留一层」 |

## 7. 与兄弟组件的分工

| 组件 | 定位 | 全景图改造后 |
|------|------|--------------|
| **分层全景图** | 分层结构 + 主 ETL 链路 + 快速点表 | 默认简线、四列主流程 |
| **知识图谱** | 复杂血缘网、跨层多跳 | 全景图详情加「在图谱中查看」 |
| **ER 图** | 实体关系、雪花模型 | 不变 |
| **数据字典** | 字段/口径 | 全景图卡片跳转字典 |

架构页 section 顺序建议：全景图 → 字典 → 图谱 → ER（**先结构后细节，先分层后网络**）。

## 9. 可选方案对比

| 方案 | 优点 | 缺点 | 建议 |
|------|------|------|------|
| **A. 在现有横向泳道上修补** | 改动小 | DIM 列过高、线乱难根治 | Phase 0–1 可做 |
| **B. 四列 + DIM 侧栏（推荐）** | 主链路清晰、可扩展 | 需改 HTML 结构生成逻辑 | Phase 2 目标 |
| **C. 改纵向自上而下** | 符合「数据从上到下流」直觉 | 与现有横向习惯不同，宽屏利用率低 | 不推荐 |
| **D. 仅保留知识图谱，删掉全景图** | 维护一份 | 丢失「分层泳道」叙事，作品集减分 | 不推荐 |

## 10. 验收标准

- [ ] 首屏 1080p 下可见完整四列层头 + 部分表卡片，无需先滚 200px chrome
- [ ] 默认状态连线 ≤ 5 条（层间主箭头 + 可选 DIM 虚线）
- [ ] 选中 `dwd_sales_wide` 后 1 秒内高亮上下游，其余淡化
- [ ] 表卡片：用途 13px 加粗、表名 11px mono，无 unstyled 文本
- [ ] 缩放 50%–150% 连线仍对齐卡片
- [ ] 零售架构页不出现「切换到互联网」按钮

---

## 11. 小结

全景图「感觉有问题」主要来自：**样式类名 bug、连线过密、控制栏过高、DIM 列布局不合理、ADS 用告警红**，而不是方向错了。  

**最小投入路径**：Phase 0 修 bug + 默认简线 + 合并工具栏，半天到一天可见改善。  

**最佳体验路径**：Phase 2 四列主流程 + DIM 侧栏 + focus 连线，才是能拿得出手册级分层图的方向。
